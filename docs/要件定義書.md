## 1. 概要

### 1.1 目的
X や Facebook のように、不特定多数のユーザーの投稿がタイムラインに流れる SNS を Web アプリとして開発する。
本アプリは **学習・ポートフォリオ** を目的とし、実際の SNS で必要になる主要な機能(認証、投稿、リアクション、フォロー、通知、リアルタイム反映、検索、モデレーション)を一通り実装することで、設計と実装の技術を身につけ、成果物として公開できる状態を目指す。

### 1.2 背景・方針
- 技術は、以前作った「トレロ風タスク管理アプリ」(以下 **taskboard**)と同じもの(React + Vite / Spring Boot / PostgreSQL / Docker)を使う。身につけた技術を使い回しながら、認証・リアルタイム配信・画像の保存など、taskboard になかった技術を新しく学ぶ。
- taskboard と同じく、**見やすさ(アクセシビリティ)を最初から考える**。状態は色だけに頼らず、必ず文字でも表示する。

### 1.3 対象ユーザー

| 区分 | 説明 |
|---|---|
| 一般ユーザー | アカウントを登録し、投稿の閲覧・作成・リアクションを行う |
| 管理者 | 一般ユーザーの機能に加え、投稿の非表示化やユーザーの利用停止を行う |
| 未ログインの訪問者 | ログイン画面・登録画面・パスワード再設定画面のみ使える |

### 1.4 スコープ
- 対象: Web ブラウザで利用する SNS アプリ(PC・スマートフォンの両方の画面幅に対応)
- 規模: 少人数(数十人程度)での利用を想定
- 対象外の機能は「7. 対象外(MVPに含めないもの)」を参照

## 2. 用語集

| 用語 | 意味 |
|---|---|
| 投稿 | ユーザーが作成するテキスト(と画像)の発言 |
| 返信 | 他の投稿に対してつける投稿(コメント) |
| タイムライン(TL) | 投稿を新しい順に並べて表示する一覧 |
| ハッシュタグ | 本文中の `#` で始まる語。同じ話題の投稿をまとめるために使う |
| メンション | 本文中の `@ユーザーID`。相手に通知が届く |
| トレンド | 直近24時間に多く使われたハッシュタグや、いいねの多い投稿 |
| ミュート | 相手に知られずに、相手の投稿を自分の画面から非表示にすること |
| ブロック | 相手とのやり取りを双方向で遮断すること |
| MVP | 最初に公開する、必要最小限の機能を備えたバージョン |
| フロントエンド | ブラウザで動く画面の部分(React で作る) |
| バックエンド | サーバーで動く部分(Spring Boot で作る)。API を提供し、データベースを操作する |
| API | 画面がサーバーにデータを頼む窓口。JSON でやり取りする |
| セッション | ログインした状態をサーバーが覚えておく仕組み。ブラウザは Cookie で自分のセッションを示す |
| SSE | Server-Sent Events。サーバーからブラウザへ、新しい出来事を即時に送り続ける仕組み。ブラウザ標準の機能で使える |
| CSRF 対策 | 他のサイトから勝手に操作を送らせる攻撃を防ぐ仕組み |
| Docker | アプリやデータベースを、PC の環境に左右されずに動かすための仕組み |

## 3. 前提・制約

| No. | 内容 |
|---|---|
| C-01 | Web アプリとして提供する。スマートフォン向けネイティブアプリは作らない |
| C-02 | 技術は taskboard と同じ構成にする(「8. 技術スタック」参照)。新しく加える部品は必要最小限にする |
| C-03 | 開発中は、自分の PC 上でサーバー・データベース・メールの確認用サーバーを動かす。どれもこの PC からだけ接続できる設定にする |
| C-04 | 公開は taskboard と同じく、AWS の小さなサーバー 1 台(メモリ 1GB 程度)に、アプリとデータベースをまとめて Docker で動かす。費用をできるだけかけない |
| C-05 | Google ログイン用の Google Cloud の設定と、AWS の準備は開発者本人が行う |
| C-06 | 使用するライブラリのバージョンは「8.6 バージョン一覧」のとおりに固定する |
| C-07 | 画面の表示言語は日本語のみ |

## 4. 機能要件

優先度はすべて **MVP**(最初のバージョンで実装する)。各機能の詳しい動きは機能定義書、画面は画面仕様定義書に書く。

### 4.1 アカウント(AUTH)

| ID | 要件 |
|---|---|
| F-AUTH-01 | メールアドレスとパスワードでアカウントを登録できる。登録時に確認メールを送り、メール内のリンクを開くと登録が完了する |
| F-AUTH-02 | Google アカウントでログイン・登録できる |
| F-AUTH-03 | ログアウトできる |
| F-AUTH-04 | パスワードを忘れた場合に、メールで再設定できる |
| F-AUTH-05 | 初回ログイン時にユーザーID(@handle)と表示名を設定する。ユーザーIDは半角英数字とアンダースコアの 3〜15 文字で、他のユーザーと重複できない |
| F-AUTH-06 | ログインしていない状態でログイン必須の画面を開くと、ログイン画面へ移動する |
| F-AUTH-07 | 利用停止中のユーザーはログインできない(停止中である旨を表示する) |

### 4.2 プロフィール(PROF)

| ID | 要件 |
|---|---|
| F-PROF-01 | プロフィールとして、ユーザーID・表示名(最大50文字)・自己紹介(最大160文字)・アイコン画像・ヘッダー画像を持つ |
| F-PROF-02 | 自分のプロフィールを編集できる |
| F-PROF-03 | プロフィール画面に、そのユーザーの投稿一覧・フォロー数・フォロワー数を表示する |
| F-PROF-04 | プロフィール画面に、返信を含む投稿一覧と、画像付き投稿のみの一覧をタブで切り替えて表示できる |

### 4.3 投稿(POST)

| ID | 要件 |
|---|---|
| F-POST-01 | テキスト最大 **1000文字** の投稿を作成できる。空の投稿はできない(画像のみの投稿は可) |
| F-POST-02 | 1投稿に画像を最大 **10枚** 添付できる。送信前にプレビューを表示し、個別に取り消せる |
| F-POST-03 | 画像ごとに代替テキスト(画像の説明文)を入力できる |
| F-POST-04 | 本文中の `#ハッシュタグ` はタグの投稿一覧へ、`@ユーザーID` はそのユーザーのプロフィールへ、URL は外部サイトへのリンクとして表示する |
| F-POST-05 | 自分の投稿の本文を編集できる。編集した投稿には「編集済み」と表示する(画像の差し替えは不可) |
| F-POST-06 | 自分の投稿を削除できる。削除前に確認を表示する |
| F-POST-07 | 投稿に返信できる。返信の文字数・画像枚数の上限は通常の投稿と同じ |
| F-POST-08 | 投稿詳細画面で、投稿本体と返信の一覧を表示する。返信先の投稿が削除された場合は「この投稿は削除されました」と表示する |
| F-POST-09 | 投稿には投稿者のアイコン・表示名・ユーザーID・投稿日時(「3分前」「10月25日」などの形式)を表示する |

### 4.4 リアクション(REACT)

| ID | 要件 |
|---|---|
| F-REACT-01 | 投稿に「いいね」をつけられる。もう一度押すと取り消せる |
| F-REACT-02 | 各投稿にいいね数・返信数を表示する |
| F-REACT-03 | いいねボタンは押した瞬間に表示を切り替え、保存に失敗した場合は元に戻してエラーを表示する |
| F-REACT-04 | 投稿をブックマークできる。もう一度押すと解除できる |
| F-REACT-05 | ブックマークした投稿の一覧を見られる。ブックマークは本人以外には見えない |

### 4.5 タイムライン(TL)

| ID | 要件 |
|---|---|
| F-TL-01 | 「すべて」タブで、全ユーザーの投稿を新しい順に表示する |
| F-TL-02 | 「フォロー中」タブで、自分とフォロー中のユーザーの投稿のみを新しい順に表示する |
| F-TL-03 | 1回に20件ずつ読み込み、一覧の下端までスクロールすると続きを自動で読み込む |
| F-TL-04 | 他のユーザーが新しく投稿すると、ページを再読み込みしなくても自動でタイムラインの先頭に追加する |
| F-TL-05 | 画面を下までスクロールしている間に新着が届いた場合も、閲覧中の位置がずれないようにする |
| F-TL-06 | 返信はタイムラインに表示しない(投稿詳細画面とプロフィール画面で表示する) |
| F-TL-07 | ブロック・ミュートしたユーザー、およびブロックされているユーザーの投稿は表示しない |
| F-TL-08 | 管理者が非表示にした投稿と、利用停止中のユーザーの投稿は表示しない |

### 4.6 フォロー(FOLLOW)

| ID | 要件 |
|---|---|
| F-FOLLOW-01 | 他のユーザーをフォロー・フォロー解除できる |
| F-FOLLOW-02 | ユーザーごとに、フォロー中の一覧とフォロワーの一覧を見られる |
| F-FOLLOW-03 | 自分自身はフォローできない |

### 4.7 通知(NOTIF)

| ID | 要件 |
|---|---|
| F-NOTIF-01 | 次のときに通知を作成する: 自分の投稿にいいねされた / 返信された / フォローされた / メンションされた |
| F-NOTIF-02 | 自分の操作による通知は作成しない(自分の投稿に自分でいいねした場合など) |
| F-NOTIF-03 | メニューに未読件数のバッジを表示し、通知が届いたら自動で即時に更新する |
| F-NOTIF-04 | 通知一覧画面を開くと、表示した通知を既読にする |
| F-NOTIF-05 | 通知をクリックすると、該当する投稿またはユーザーの画面へ移動する |
| F-NOTIF-06 | ブロック・ミュートしているユーザーからの通知は作成しない |

### 4.8 トレンド(TREND)

| ID | 要件 |
|---|---|
| F-TREND-01 | 直近24時間に使われたハッシュタグを使用件数の多い順に上位10件表示する |
| F-TREND-02 | 直近24時間に投稿された投稿のうち、いいね数の多い投稿を「人気投稿」として表示する |
| F-TREND-03 | トレンドのハッシュタグをクリックすると、そのタグを含む投稿の一覧を表示する |

### 4.9 検索(SEARCH)

| ID | 要件 |
|---|---|
| F-SEARCH-01 | キーワードを含む投稿を検索できる(日本語の文章に対応する) |
| F-SEARCH-02 | ユーザーID・表示名でユーザーを検索できる |
| F-SEARCH-03 | ハッシュタグ名で検索でき、そのタグを含む投稿の一覧を表示する |
| F-SEARCH-04 | 検索結果は「投稿 / ユーザー / ハッシュタグ」のタブで切り替えて表示する |
| F-SEARCH-05 | 検索結果からも、ブロック・ミュート・非表示・利用停止の対象は除く |

### 4.10 ブロック・ミュート(BLOCK)

| ID | 要件 |
|---|---|
| F-BLOCK-01 | 他のユーザーをミュートできる。ミュートした相手の投稿は自分の画面に表示されなくなる。相手には分からない |
| F-BLOCK-02 | 他のユーザーをブロックできる。ブロックすると、お互いの投稿が見えなくなり、お互いのフォローが解除され、お互いにフォロー・返信・いいねができなくなる |
| F-BLOCK-03 | 設定画面でブロック・ミュート中のユーザー一覧を確認し、解除できる |

### 4.11 管理者機能(ADMIN)

| ID | 要件 |
|---|---|
| F-ADMIN-01 | 管理者権限を持つユーザーだけが管理者画面(`/admin`)を開ける。それ以外のユーザーには「ページが見つかりません」を表示する |
| F-ADMIN-02 | ユーザー一覧を表示し、ユーザーID・表示名で検索できる |
| F-ADMIN-03 | 投稿一覧を表示し、本文で検索できる |
| F-ADMIN-04 | 投稿を非表示にする・非表示を解除することができる |
| F-ADMIN-05 | ユーザーを利用停止にする・停止を解除することができる |
| F-ADMIN-06 | 管理者権限の付与は、データベースを直接操作して行う(画面からは付与しない) |

## 5. 非機能要件

### 5.1 セキュリティ(SEC)

| ID | 要件 |
|---|---|
| NF-SEC-01 | データの作成・変更・削除のたびに、サーバー側(Service 層)で「本人のデータか」「管理者か」を確認する。画面の表示を隠すだけに頼らない |
| NF-SEC-02 | 管理者の API は、サーバー側で管理者権限を確認してから実行する |
| NF-SEC-03 | パスワードは BCrypt で変換してから保存し、元のパスワードは保存しない。パスワードは 8〜72 文字 |
| NF-SEC-04 | ログイン状態はサーバーのセッションで管理し、Cookie には `HttpOnly`(画面のプログラムから読めない)と `SameSite=Lax` を付ける。公開時は `Secure`(HTTPS のときだけ送る)も付ける |
| NF-SEC-05 | データを変更する API(POST / PUT / DELETE)には CSRF 対策を行う |
| NF-SEC-06 | 入力値は画面側とサーバー側の両方で検証する |
| NF-SEC-07 | 投稿本文は HTML として解釈せず、文字列として表示する(スクリプトの埋め込みを防ぐ) |
| NF-SEC-08 | データベースのパスワード、Google ログインの秘密鍵、メール送信のパスワードは、ファイルに直接書かず環境変数(`.env`。git に入れない)から渡す |
| NF-SEC-09 | 開発中は、サーバー(8080番)・データベース(5432番)・メール確認用サーバー(1025番・8025番)を、この PC からだけ接続できる設定にする |
| NF-SEC-10 | 公開時は、データベースを外に公開せず、アプリのコンテナからだけ接続する。通信は HTTPS にする |
| NF-SEC-11 | 同じメールアドレスへのログイン失敗が 5 回続いたら、15 分間そのアカウントへのログインを受け付けない |

### 5.2 画像(IMG)

| ID | 要件 |
|---|---|
| NF-IMG-01 | 受け付ける形式は JPEG / PNG / WebP / GIF のみ。拡張子ではなく、ファイルの中身で形式を確かめる |
| NF-IMG-02 | 1枚あたり 5MB まで。送信前にブラウザ側で長辺 2048px 程度に縮小する |
| NF-IMG-03 | 画像はサーバーのフォルダ(公開時は Docker のボリューム)に、推測できないファイル名で保存する |

### 5.3 性能(PERF)

| ID | 要件 |
|---|---|
| NF-PERF-01 | タイムラインは1回20件ずつ読み込む |
| NF-PERF-02 | 他のユーザーの新着投稿・通知は、発生からおおむね数秒以内に画面へ反映する(SSE で配信する) |
| NF-PERF-03 | いいね・ブックマーク・フォローのボタンは、押した瞬間に表示が切り替わる |
| NF-PERF-04 | 公開用のサーバー(メモリ 1GB 程度)で、アプリとデータベースを合わせて動かせる |

### 5.4 見やすさ・使いやすさ(A11Y)

| ID | 要件 |
|---|---|
| NF-A11Y-01 | スマートフォン(幅 375px)から PC まで、横スクロールなしで表示できる |
| NF-A11Y-02 | すべての操作をキーボードだけで行える |
| NF-A11Y-03 | 画像には代替テキストを設定できる |
| NF-A11Y-04 | 文字と背景の色の差(コントラスト)を十分に取る。taskboard と同じく、大きめの文字を標準にする |
| NF-A11Y-05 | ライトモードとダークモードに対応する(端末の設定に合わせ、手動でも切り替えられる) |
| NF-A11Y-06 | 状態(いいね済み・未読・エラーなど)は、色だけに頼らず文字やアイコンの形でも表示する |

### 5.5 品質(QA)

| ID | 要件 |
|---|---|
| NF-QA-01 | サーバーの処理(入力チェック、権限の確認、本文からのハッシュタグ・メンションの抽出など)は、JUnit の自動テストで確認する。データベースを使うテストは Testcontainers で本物の PostgreSQL を動かして行う |
| NF-QA-02 | 登録・投稿・いいね・フォローなどの主要な操作の流れは、ブラウザ操作の自動テスト(Playwright)で確認する |
| NF-QA-03 | 画面のコードは oxlint で書き方をそろえる |

### 5.6 運用(OPS)

| ID | 要件 |
|---|---|
| NF-OPS-01 | サーバーのログをファイルに保存する(10MB ごとに切り替え、30日分を残す。git には入れない)。taskboard と同じ設定にする |
| NF-OPS-02 | 動作確認用のテストデータを入れる仕組み(プロファイル `seed`)を用意する |

### 5.7 対応ブラウザ(ENV)

| ID | 要件 |
|---|---|
| NF-ENV-01 | Chrome / Edge / Safari / Firefox の最新版に対応する |

## 6. 画面一覧

各画面の詳しい仕様は画面仕様定義書に書く。

| 画面ID | 画面名 | URL | 主な機能 | ログイン |
|---|---|---|---|---|
| S-01 | ログイン | `/login` | メール+パスワード、Google でログイン | 不要 |
| S-02 | 新規登録 | `/signup` | メール+パスワード、Google で登録 | 不要 |
| S-03 | パスワード再設定 | `/reset-password` | 再設定メールの送信・新パスワード設定 | 不要 |
| S-04 | 初期設定 | `/onboarding` | ユーザーID・表示名の設定 | 必要 |
| S-05 | ホーム | `/` | タイムライン(すべて/フォロー中)、投稿作成 | 必要 |
| S-06 | 投稿詳細 | `/posts/{id}` | 投稿本体、返信一覧、返信作成 | 必要 |
| S-07 | プロフィール | `/users/{handle}` | プロフィール、投稿一覧、フォロー操作、ブロック・ミュート | 必要 |
| S-08 | フォロー・フォロワー一覧 | `/users/{handle}/following`, `/users/{handle}/followers` | ユーザー一覧 | 必要 |
| S-09 | 通知 | `/notifications` | 通知一覧、既読化 | 必要 |

## 8. 技術スタック

taskboard と同じ構成にする。taskboard になかった機能(ログイン、メール送信、リアルタイム配信、画面の切り替え)のために、次の部品だけを新しく加える。

| 新しく加える部品 | 用途 |
|---|---|
| Spring Security | ログイン・ログアウト、権限の確認、CSRF 対策 |
| Spring Security OAuth2 Client | Google ログイン |
| Spring Boot Mail | 確認メール・パスワード再設定メールの送信 |
| Mailpit(開発中のみ、Docker) | 送ったメールを外に出さずに受け取り、ブラウザで確認する |
| react-router | 画面(URL)の切り替え |
| Playwright | ブラウザ操作の自動テスト |

### 8.1 全体の構成図

```
[ブラウザ]
  React で作った画面(フロントエンド / 入口は index.html)
        │  fetch で JSON をやり取り(REST API)
        │  EventSource で新着投稿・通知を受け取る(SSE)
        ▼
[Spring Boot サーバー](バックエンド / http://localhost:8080)
  Spring Security(ログイン状態・権限・CSRF の確認)
  Controller(API の窓口)→ Service(処理・権限の確認)→ Repository(DB操作)
        │  Spring Data JPA(localhost:5432 に接続)      │ 画像ファイル
        ▼                                                 ▼
[PostgreSQL データベース]                        [画像の保存フォルダ]
  Docker のコンテナ「sns-db」で動く                  uploads/(git に入れない)
  データは Docker のボリューム「sns-db-data」に保存

  ※ メール送信: 開発中は Mailpit(Docker のコンテナ「sns-mail」)へ送る
```

開発中と完成後で、画面の配信元が変わる(taskboard と同じ)。
- **開発中**: React の開発サーバー(Vite / `http://localhost:5173`)が画面を配信し、`/api`・`/media`・Google ログイン用の URL へのアクセスを Spring Boot(8080)に中継する
- **完成後**: `npm run build` で React の画面を HTML/JS/CSS に変換して `src/main/resources/static/` に出力し、Spring Boot が画面も API もまとめて配信する。`/api` 以外の URL(`/users/abc` など)は、Spring Boot が `index.html` を返し、React が画面を切り替える

### 8.2 フロントエンド
- ライブラリ: React 19
- 画面の切り替え: react-router 8
- 開発ツール: Vite 8(開発サーバーとビルド)/ Node.js・npm
- 言語: JavaScript(JSX)。TypeScript は使わない(taskboard と同じ)
- 置き場所: `frontend/`
- サーバーとの通信: fetch で REST API を呼ぶ。新着投稿と通知は、ブラウザ標準の `EventSource`(SSE)で受け取る
- 画像の縮小: ブラウザ標準の canvas で、送信前に縮小する(追加の部品は使わない)
- 日時の表示: ブラウザ標準の `Intl.RelativeTimeFormat` / `Intl.DateTimeFormat` で「3分前」「10月25日」の形にする(追加の部品は使わない)
- スタイル: CSS(大きめの文字サイズ・高コントラストな配色をデフォルトで組み込む。ダークモードは CSS の変数で切り替える)
- 部品(コンポーネント)の構成は、画面仕様定義書に書く

### 8.3 バックエンド
- 言語: Java 21(Microsoft Build of OpenJDK)
- フレームワーク: Spring Boot 4.1
  - Spring Web MVC … REST API、SSE、画面ファイル・画像の配信
  - Spring Data JPA … データベース操作
  - Bean Validation(Hibernate Validator)… 入力チェック
  - Spring Security … ログイン(セッション)、権限の確認、CSRF 対策、パスワードの変換(BCrypt)
  - Spring Security OAuth2 Client … Google ログイン
  - Spring Boot Mail … メール送信
- ビルドツール: Maven(プロジェクト同梱の Maven Wrapper `mvnw` を使うため、Maven 本体のインストールは不要)
- 置き場所: リポジトリの一番上(`pom.xml`・`src/`)
- 接続設定: `src/main/resources/application.properties`。接続先・パスワードなどは環境変数で上書きできる

| 環境変数 | 内容 |
|---|---|
| `DB_URL` / `DB_USERNAME` / `DB_PASSWORD` | データベースの接続先・ユーザー名・パスワード |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | Google ログインの設定 |
| `MAIL_HOST` / `MAIL_PORT` / `MAIL_USERNAME` / `MAIL_PASSWORD` / `MAIL_FROM` | メール送信の設定 |
| `APP_BASE_URL` | メール内のリンクに使う、アプリの URL |
| `UPLOAD_DIR` | 画像の保存フォルダ |

- API の一覧と詳しい仕様は、機能定義書に書く

### 8.4 データベース
- 種類: PostgreSQL 18
- 動かし方: Docker Desktop 上のコンテナとして動かす(設定ファイルは `compose.yaml`)
- コンテナ名: `sns-db`
- 接続先: `localhost:5432`(自分の PC からだけ接続できる設定)
- データベース名 / ユーザー名 / パスワード: すべて `sns`(自分の PC 内だけで使う開発用の値)
- データの保存先: Docker のボリューム `sns-db-data`(コンテナを止めたり削除したりしてもデータは残る)
- テーブル: Spring Boot(JPA)がプログラムの内容に合わせて自動で作成・更新する(taskboard と同じ)
- 検索: 本文やユーザー名の部分一致(大文字・小文字は区別しない)で探す。少人数での利用を想定しているため、検索専用の仕組みは使わない
- テーブルの一覧と各列の定義は、機能定義書に書く

### 8.5 メールの確認用サーバー(開発中のみ)
- Mailpit を Docker のコンテナ `sns-mail` として動かす(`compose.yaml` に含める)
- アプリが送ったメールは外には届かず、Mailpit が受け取る。`http://localhost:8025` で受け取ったメールを見られる
- 公開時は、実際にメールを送れる SMTP サービスを使う(Amazon SES などを想定。公開の段階で決める)

### 8.7 公開用の構成
taskboard と同じ方法で公開する。
- `Dockerfile`: 画面(React)とサーバー(Spring Boot)を1つのイメージにまとめる。3段階で作り、最後のイメージには Java の実行環境とアプリだけを入れる。Java のメモリは最大 256MB に抑える
- `compose.prod.yaml`: アプリ、PostgreSQL、入口の Caddy(HTTPS)を一緒に動かす。プロジェクト名は `sns-prod` で、開発用の `compose.yaml` とは別(開発用のデータに影響しない)。画像は Docker のボリューム `uploads` に保存する
- `.env.example`: 公開用の設定の見本(`DB_PASSWORD`・`SITE_ADDRESS`・Google ログイン・メール送信の設定)。コピーして `.env` を作る
- `deploy/aws/`: AWS(東京、EC2 t4g.micro、Amazon Linux 2023)で公開するためのスクリプトと設定。taskboard の `deploy/aws/` を流用する
- セキュリティグループは 80/443 のみ開放する
- Google ログインを使うため、公開するアドレス(`<IP>.sslip.io` など)を Google Cloud の「承認済みのリダイレクト URI」に登録する

### 8.8 実行環境・起動方法

**最初に(共通): データベースとメールの確認用サーバーを起動する**
1. Docker Desktop を起動する
2. リポジトリの一番上で `docker compose up -d` を実行する(PostgreSQL と Mailpit が起動する)

**開発中(画面を作りながら確認するとき)**
1. リポジトリの一番上で `mvnw spring-boot:run` を実行して Spring Boot を起動する
2. 別の画面で `frontend` フォルダに移動し、`npm run dev` を実行して React の開発サーバーを起動する
3. ブラウザで `http://localhost:5173/` を開く(ファイルを保存するとすぐ画面に反映される)
4. 確認メールは `http://localhost:8025`(Mailpit)で見る

**完成後(ふだん使うとき)**
1. `frontend` フォルダで `npm run build` を実行する(画面を変更したときだけ必要)
2. リポジトリの一番上で `mvnw spring-boot:run` を実行する
3. ブラウザで `http://localhost:8080/` を開く

**動作確認用のテストデータを入れたいとき**
- `mvnw spring-boot:run "-Dspring-boot.run.profiles=seed"` で起動すると、データを空にしてからテストデータ(ユーザー数人と投稿・いいね・フォロー)を入れ直す。今までのデータは消える

※ `npm run build` で作られるファイル(`src/main/resources/static/`)、画像の保存フォルダ(`uploads/`)、ログ(`logs/`)は git にコミットしない。

## 1. 共通の仕様

### 1.1 API の基本
- API の URL はすべて `/api` で始まる。データは JSON でやり取りする(画像を送るときだけ `multipart/form-data`)
- 文字コードは UTF-8
- 日時は ISO 8601 形式の UTC で返す(例: `"2026-11-01T03:15:00Z"`)。画面で日本時間に変えて表示する
- ID は 1 から増えていく整数
- 文字数は、見た目の 1 文字を 1 文字として数える(絵文字も 1 文字)。前後の空白と改行は取り除いてから数える

### 1.2 ログイン状態と CSRF 対策
- ログインすると、サーバーがセッションを作り、ブラウザに Cookie(`SESSION`)を渡す。以後の API 呼び出しには、ブラウザが自動でこの Cookie を付ける
- サーバーは Cookie `XSRF-TOKEN` に CSRF 対策の値を入れて渡す。画面は、データを変更する API(POST / PUT / DELETE)を呼ぶときに、この値をヘッダー `X-XSRF-TOKEN` に入れて送る。値がない・違うときは `403`
- セッションの有効期間は、最後の操作から 30 日

### 1.3 ステータスコード

| コード | 意味 | 主な場面 |
|---|---|---|
| 200 | 成功(本文あり) | 取得・更新 |
| 201 | 作成した | 登録・投稿 |
| 204 | 成功(本文なし) | 削除・いいねの取り消しなど |
| 400 | 入力が正しくない | 入力チェックの失敗、JSON が壊れている |
| 401 | ログインしていない | セッションがない・切れた |
| 403 | 権限がない | 他人の投稿の編集、管理者以外の管理者 API、CSRF の値が違う、初期設定が済んでいない |
| 404 | 見つからない | 存在しない・削除された・ブロックで見えないデータ |
| 409 | 他のデータとぶつかる | ユーザーID・メールアドレスの重複 |
| 413 | 大きすぎる | 画像が 5MB を超える |
| 423 | ロック中 | ログインの失敗が続いた |
| 429 | 回数が多すぎる | 確認メールの再送を短い間に繰り返した |

### 1.4 エラーのときの JSON
taskboard と同じ形にする。

```json
{
  "message": "入力内容に誤りがあります",
  "errors": [
    { "field": "text", "message": "1000文字以内で入力してください" }
  ]
}
```

- `errors` は入力チェックのときだけ中身が入る(それ以外は空の配列)
- `message` は、そのまま画面に表示できる日本語にする

### 1.5 一覧の続きの読み込み(カーソル方式)
タイムラインなど、新しい順に並ぶ一覧は、次の方法で続きを読み込む。

- 1回目: `GET /api/timeline?tab=all`(新しいものから最大 20 件)
- 2回目以降: 前の結果の `nextCursor` を `before` に渡す → `GET /api/timeline?tab=all&before=1234`
- `nextCursor` が `null` なら、それ以上はない
- `limit` で件数を変えられる(1〜50、省略時 20)

```json
{
  "items": [ /* 投稿など */ ],
  "nextCursor": 1234
}
```

ページ番号ではなく「この ID より古いもの」で続きを取るため、読み込みの途中で新しい投稿が増えても、同じ投稿が二重に出たり抜けたりしない。

### 1.6 投稿の表示ルール(どの投稿が見えるか)
一覧(タイムライン・プロフィール・検索・トレンド・ハッシュタグ・ブックマーク)に出す投稿は、見る人(ログイン中のユーザー)ごとに、次をすべて満たすものに絞る。

| No. | ルール | 関連要件 |
|---|---|---|
| V-01 | 削除されていない | F-POST-06 |
| V-02 | 管理者に非表示にされていない | F-TL-08 |
| V-03 | 投稿者が利用停止中でない | F-TL-08 |
| V-04 | 投稿者と見る人の間に、どちら向きのブロックもない | F-TL-07 |
| V-05 | 見る人が投稿者をミュートしていない | F-TL-07 |

例外として、自分のプロフィールの投稿一覧では、管理者に非表示にされた自分の投稿(V-02)も、その印を付けて表示する(3.12)。

投稿詳細(1件の取得)では、V-01〜V-03 に当てはまる投稿は「表示できない投稿」として返し(1.7 の `unavailable`)、V-04 に当てはまる場合は `404` を返す。ミュートした相手の投稿も、詳細画面では表示する(自分で開いたため)。

### 1.7 投稿の JSON
投稿を返す API は、すべてこの形を使う。

```json
{
  "id": 1234,
  "author": {
    "id": 7,
    "handle": "taro_dev",
    "displayName": "たろう",
    "avatarUrl": "/media/avatars/3f9c....webp"
  },
  "text": "今日は #SpringBoot の勉強をしました @hanako さんありがとう",
  "images": [
    { "url": "/media/posts/2026/11/a1b2....webp", "alt": "ノートパソコンの画面", "width": 1600, "height": 1200 }
  ],
  "replyTo": { "id": 1200, "authorHandle": "hanako", "unavailable": false },
  "likeCount": 5,
  "replyCount": 2,
  "likedByMe": true,
  "bookmarkedByMe": false,
  "mine": false,
  "hidden": false,
  "createdAt": "2026-11-01T03:15:00Z",
  "editedAt": null,
  "unavailable": false
}
```

- `replyTo` は返信でないとき `null`。返信先が削除・非表示などで見られないときは `"unavailable": true`(画面は「この投稿は削除されました」と表示)
- `editedAt` は編集されていないとき `null`(画面は値があれば「編集済み」と表示)
- `mine` は自分の投稿なら `true`(画面は編集・削除のメニューを出す)
- `hidden` は管理者に非表示にされた投稿なら `true`。非表示の投稿は本人にしか返さない(画面は「管理者により非表示になりました」と表示する)
- `unavailable` が `true` のときは、`id` 以外を空にして返す
- 本文の中のハッシュタグ・メンション・URL のリンク化は画面で行う(サーバーは本文をそのまま返す)

### 1.8 ユーザーの JSON(一覧用)

```json
{
  "id": 7,
  "handle": "taro_dev",
  "displayName": "たろう",
  "avatarUrl": "/media/avatars/3f9c....webp",
  "bio": "Java を勉強中です",
  "followedByMe": true,
  "followsMe": false
}
```

`avatarUrl` は未設定のとき `null`(画面は標準のアイコンを表示)。

## 2. 権限の一覧

| 操作 | 未ログイン | 初期設定前 | 一般ユーザー | 管理者 | 利用停止中 |
|---|---|---|---|---|---|
| 登録・ログイン・パスワード再設定 | ○ | — | — | — | ×(ログイン不可) |
| 初期設定(ユーザーID・表示名) | × | ○ | — | — | × |
| 投稿・一覧の閲覧 | × | × | ○ | ○ | × |
| 投稿・返信・いいね・ブックマーク・フォロー | × | × | ○ | ○ | × |
| 自分の投稿の編集・削除 | × | × | ○ | ○ | × |
| 他人の投稿の編集・削除 | × | × | × | ×(非表示化のみ) | × |
| ブロック・ミュート | × | × | ○ | ○ | × |
| 管理者画面・管理者 API | × | × | × | ○ | × |

- 未ログインで API を呼ぶと `401`、初期設定前に初期設定以外の API を呼ぶと `403`(`message`: 「初期設定を完了してください」)
- 利用停止にされたユーザーは、次に API を呼んだときにセッションを消され、`401` になる

## 3. 機能ごとの定義

### 3.1 アカウント(AUTH)

#### メールアドレスでの登録(F-AUTH-01)
処理の流れ:
1. 画面からメールアドレスとパスワードを送る
2. 入力をチェックし、メールアドレスが登録済みでないかを確かめる
3. パスワードを BCrypt で変換して、「確認前」の状態でユーザーを保存する
4. 確認用の値(推測できない 32 バイトの乱数)を作り、変換した値をデータベースに保存して、確認用リンク `{APP_BASE_URL}/verify-email?token=…` をメールで送る。リンクの有効期間は 24 時間、1回だけ使える
5. リンクを開くと、画面が値をサーバーに送り、正しければ「確認済み」にしてログイン状態にし、初期設定画面へ進む

入力チェック:

| 項目 | ルール | エラーのメッセージ |
|---|---|---|
| `email` | 必須。メールアドレスの形。254 文字以内。大文字・小文字は区別しない(小文字にして保存) | 「メールアドレスの形で入力してください」 |
| `password` | 必須。8〜72 文字 | 「パスワードは8文字以上72文字以内で入力してください」 |

ルール:
- 登録済みのメールアドレスのときは `409`(「このメールアドレスは登録済みです」)
- 確認前のまま 24 時間たったユーザーは、同じメールアドレスで登録し直せる(古いユーザーを消して作り直す)
- 確認メールの再送は、同じメールアドレスで 1 分に 1 回まで(超えると `429`)

#### Google ログイン(F-AUTH-02)
処理の流れ:
1. 画面の「Google でログイン」から `/oauth2/authorization/google` を開く(Spring Security が Google の画面へ移動させる)
2. Google で許可すると `/login/oauth2/code/google` に戻り、サーバーが Google のユーザー情報(ID・メールアドレス・確認済みか)を受け取る
3. 次の順にユーザーを決めてログイン状態にする
   - Google の ID が登録済み → そのユーザー
   - 同じメールアドレスのユーザーがいて、Google 側でメールアドレスが確認済み → そのユーザーに Google の ID を結びつける
   - どちらでもない → 「確認済み」の新しいユーザーを作る
4. 初期設定前なら `/onboarding`、済んでいれば `/` へ移動する。利用停止中なら `/login?error=suspended` へ移動する

#### ログイン・ログアウト(F-AUTH-03, F-AUTH-07)
- ログイン: メールアドレスとパスワードを送る。正しければセッションを作り、ユーザーの情報を返す
- 失敗のときは、メールアドレスとパスワードのどちらが違うかは教えない(「メールアドレスまたはパスワードが違います」)
- メールアドレスの確認前は `403`(「メールアドレスの確認が済んでいません」。確認メールの再送ボタンを出す)
- 利用停止中は `403`(「このアカウントは利用停止中です」)
- 同じメールアドレスでの失敗が 5 回続いたら、15 分間ロックする。ロック中は `423`(「ログインの失敗が続いたため、15分間ログインできません」)。ログインに成功したら失敗の回数を 0 に戻す
- ログアウト: セッションを消す。SSE の接続も切れる

#### パスワード再設定(F-AUTH-04)
1. メールアドレスを送る。登録の有無にかかわらず、同じ「メールを送りました」を返す(登録済みかどうかを知られないため)
2. 登録済みで、パスワードを持つユーザーなら、再設定用のリンク `{APP_BASE_URL}/reset-password?token=…` を送る。有効期間は 1 時間、1回だけ使える
3. リンクから新しいパスワードを送ると、パスワードを変え、そのユーザーの他のセッションをすべて消す
4. 期限切れ・使用済みの値は `400`(「このリンクは期限切れか、すでに使われています」)

#### 初期設定(F-AUTH-05)

| 項目 | ルール | エラーのメッセージ |
|---|---|---|
| `handle` | 必須。半角英数字と `_` の 3〜15 文字。大文字・小文字は区別せずに重複を確かめる(表示は入力したとおり) | 「ユーザーIDは半角英数字と_の3〜15文字で入力してください」 |
| `displayName` | 必須。1〜50 文字 | 「表示名は1〜50文字で入力してください」 |

- 重複のときは `409`(「このユーザーIDは使われています」)
- 次の語はユーザーIDに使えない(管理者や運営と見分けがつかなくなるため。大文字・小文字は区別しない): `admin`・`administrator`・`root`・`system`・`support`・`official`
- ユーザーIDは初期設定のあとは変えられない
- 入力中に使えるかを確かめる API も用意する(`GET /api/handles/{handle}/availability`)

#### ログインが必要な画面の保護(F-AUTH-06)
画面は最初に `GET /api/auth/me` を呼ぶ。`401` ならログイン画面へ、初期設定前なら初期設定画面へ移動する。どの画面にいたかを覚えておき、ログイン後にその画面へ戻す。

#### API

| 操作 | メソッド | URL | 成功 |
|---|---|---|---|
| 登録 | POST | `/api/auth/signup` | 201 |
| メールアドレスの確認 | POST | `/api/auth/verify-email` | 200 |
| 確認メールの再送 | POST | `/api/auth/verify-email/resend` | 204 |
| ログイン | POST | `/api/auth/login` | 200 |
| ログアウト | POST | `/api/auth/logout` | 204 |
| ログイン中のユーザーの取得 | GET | `/api/auth/me` | 200 |
| 画面の設定の取得(Google ログインが使えるか。CSRF 対策の Cookie もここで受け取る。ログイン不要) | GET | `/api/auth/config` | 200 |
| パスワード再設定メールの送信 | POST | `/api/auth/password-reset` | 204 |
| 新しいパスワードの設定 | POST | `/api/auth/password-reset/confirm` | 204 |
| 初期設定 | POST | `/api/me/onboarding` | 200 |
| ユーザーIDが使えるかの確認 | GET | `/api/handles/{handle}/availability` | 200 |
| Google ログインの開始 | GET | `/oauth2/authorization/google` | Google へ移動 |

送る JSON の例:
- 登録・ログイン: `{"email": "taro@example.com", "password": "********"}`
- メールアドレスの確認: `{"token": "…"}`
- 新しいパスワードの設定: `{"token": "…", "password": "********"}`
- 初期設定: `{"handle": "taro_dev", "displayName": "たろう"}`

`GET /api/auth/me` が返す JSON:
```json
{
  "id": 7,
  "email": "taro@example.com",
  "handle": "taro_dev",
  "displayName": "たろう",
  "avatarUrl": null,
  "role": "USER",
  "onboarded": true,
  "unreadNotificationCount": 3
}
```
`role` は `USER`(一般ユーザー)か `ADMIN`(管理者)。初期設定前は `handle` が `null`、`onboarded` が `false`。

### 3.2 プロフィール(PROF)

#### プロフィールの表示(F-PROF-01, F-PROF-03, F-PROF-04)
`GET /api/users/{handle}` が返す JSON:
```json
{
  "id": 7,
  "handle": "taro_dev",
  "displayName": "たろう",
  "bio": "Java を勉強中です",
  "avatarUrl": "/media/avatars/3f9c....webp",
  "headerUrl": null,
  "followingCount": 12,
  "followerCount": 30,
  "postCount": 85,
  "joinedAt": "2026-10-25T05:00:00Z",
  "followedByMe": false,
  "followsMe": true,
  "blockedByMe": false,
  "mutedByMe": false,
  "me": false
}
```
- 利用停止中のユーザー、自分をブロックしているユーザーは `404`
- 自分がブロックしている相手は表示するが、投稿一覧は返さない(画面は「ブロックしています」と表示)

投稿一覧 `GET /api/users/{handle}/posts?tab=…` の `tab`:

| 値 | 内容 |
|---|---|
| `posts`(省略時) | 返信以外の投稿 |
| `replies` | 返信を含むすべての投稿 |
| `media` | 画像付きの投稿(返信を含む) |

#### プロフィールの編集(F-PROF-02)

| 項目 | ルール |
|---|---|
| `displayName` | 必須。1〜50 文字 |
| `bio` | 任意。160 文字以内。空にすると未設定 |
| アイコン画像 | 任意。画像のルールは 3.3 と同じ。正方形に切り取らず、画面で丸く表示する |
| ヘッダー画像 | 任意。画像のルールは 3.3 と同じ |

- 画像を変えたら、古い画像ファイルを消す
- 画像を消す API も用意する(未設定に戻す)

#### API

| 操作 | メソッド | URL | 成功 |
|---|---|---|---|
| プロフィールの取得 | GET | `/api/users/{handle}` | 200 |
| ユーザーの投稿一覧 | GET | `/api/users/{handle}/posts?tab=&before=` | 200 |
| プロフィールの更新 | PUT | `/api/me/profile` | 200 |
| アイコン画像の変更 | PUT | `/api/me/avatar`(multipart、項目名 `file`) | 200 |
| アイコン画像の削除 | DELETE | `/api/me/avatar` | 204 |
| ヘッダー画像の変更 | PUT | `/api/me/header`(multipart、項目名 `file`) | 200 |
| ヘッダー画像の削除 | DELETE | `/api/me/header` | 204 |

### 3.3 投稿(POST)

#### 投稿の作成・返信(F-POST-01〜03, F-POST-07)
`POST /api/posts` に `multipart/form-data` で送る。

| 項目名 | 内容 | ルール |
|---|---|---|
| `text` | 本文 | 1000 文字以内。画像がないときは必須 |
| `replyToId` | 返信先の投稿の ID | 任意。返信のときだけ |
| `images` | 画像ファイル(複数) | 0〜10 枚。1枚 5MB まで。JPEG / PNG / WebP / GIF |
| `alts` | 画像ごとの代替テキスト | `images` と同じ順番・同じ数。1つ 1000 文字以内。空でもよい |

処理の流れ:
1. 入力をチェックする(本文も画像もないときは「本文か画像のどちらかを入力してください」)
2. 返信のときは、返信先が見られる投稿か(1.6 の V-01〜V-04)を確かめる。見られなければ `404`
3. 画像の中身を読んで形式を確かめ、縦横の大きさを調べる。形式が違えば `400`、大きすぎれば `413`
4. 画像を `uploads/posts/年/月/推測できない名前.拡張子` に保存する
5. 投稿・画像・ハッシュタグをまとめて保存する(どれかが失敗したら全部取り消し、保存した画像ファイルも消す)
6. 通知を作る(返信なら返信先の投稿者へ「返信」、本文のメンション相手へ「メンション」)
7. 返信でなければ、SSE で他のユーザーに新着投稿を配信する(3.8)
8. `201` と投稿の JSON(1.7)を返す

#### 本文からの抽出ルール(F-POST-04)
サーバー(ハッシュタグ・メンションの保存と通知)と画面(リンク化)で同じルールを使う。

| 種類 | ルール | 例 |
|---|---|---|
| ハッシュタグ | `#` の後ろに、文字(漢字・かな・英字など)・数字・`_`・`ー` が 1〜50 文字続くもの。数字だけのものは除く。前の文字が英数字のときは対象外。大文字・小文字と全角・半角の英数字はそろえて(小文字の半角にして)同じタグとして扱う | `#SpringBoot` → `springboot` |
| メンション | `@` の後ろに半角英数字と `_` が 3〜15 文字続き、そのユーザーIDのユーザーがいるもの | `@hanako` |
| URL | `http://` または `https://` で始まり、空白までの部分 | `https://example.com/` |

- 同じ投稿の中に同じタグ・同じ相手が何度出ても、1回として数える
- 1つの投稿のメンションの通知は、最初の 10 人まで

#### 投稿の取得(F-POST-08, F-POST-09)
- `GET /api/posts/{id}`: 投稿 1 件。表示ルールは 1.6 のとおり
- `GET /api/posts/{id}/replies`: 返信の一覧。**古い順**(会話の流れの順)に並べ、続きは `after` に最後の ID を渡して取る
- 返信の返信も同じ投稿詳細画面の形で表示する(返信をクリックすると、その返信の詳細画面に移る)

#### 投稿の編集(F-POST-05)
- `PUT /api/posts/{id}` に `{"text": "…"}` を送る。本文のルールは作成と同じ(画像がない投稿で本文を空にはできない)
- 自分の投稿でなければ `403`
- `editedAt` に今の日時を入れる。ハッシュタグを付け直す
- 編集で新しく増えたメンションの相手にだけ、通知を作る

#### 投稿の削除(F-POST-06)
- `DELETE /api/posts/{id}`。自分の投稿でなければ `403`
- 投稿の行は残して「削除済み」にし、本文を空にする(返信先として「この投稿は削除されました」と表示するため)。画像ファイルは消す
- その投稿へのいいね・ブックマーク・ハッシュタグの対応・通知は消す
- SSE で「削除された」ことを配信し、開いている画面から消す
- `204` を返す

#### API

| 操作 | メソッド | URL | 成功 |
|---|---|---|---|
| 投稿・返信の作成 | POST | `/api/posts` | 201 |
| 投稿の取得 | GET | `/api/posts/{id}` | 200 |
| 返信の一覧 | GET | `/api/posts/{id}/replies?after=` | 200 |
| 投稿の編集 | PUT | `/api/posts/{id}` | 200 |
| 投稿の削除 | DELETE | `/api/posts/{id}` | 204 |
| 画像の取得 | GET | `/media/{保存場所}` | 200(ログインが必要) |

### 3.4 リアクション(REACT)

#### いいね(F-REACT-01〜03)
- `PUT /api/posts/{id}/like` でいいね、`DELETE /api/posts/{id}/like` で取り消し
- すでにいいね済みでも、もう一度 `PUT` してエラーにしない(何度送っても同じ結果)。取り消しも同じ
- 見られない投稿(1.6)は `404`。ブロックの関係にある相手の投稿は `403`
- 返す JSON: `{"liked": true, "likeCount": 6}`
- いいねしたら、投稿者に「いいね」の通知を作る。同じ人が取り消して付け直しても、通知は増やさない(前の通知の日時を新しくして未読に戻す)

#### ブックマーク(F-REACT-04, F-REACT-05)
- `PUT /api/posts/{id}/bookmark` で保存、`DELETE /api/posts/{id}/bookmark` で解除。何度送っても同じ結果
- 返す JSON: `{"bookmarked": true}`
- 一覧 `GET /api/bookmarks?before=`: **ブックマークした新しい順**。表示ルール(1.6)で見えなくなった投稿は一覧に出さない(ブックマーク自体は残す)
- ブックマークは本人しか取得できない(他人のブックマークを見る API はない)

#### API

| 操作 | メソッド | URL | 成功 |
|---|---|---|---|
| いいね | PUT | `/api/posts/{id}/like` | 200 |
| いいねの取り消し | DELETE | `/api/posts/{id}/like` | 200 |
| ブックマーク | PUT | `/api/posts/{id}/bookmark` | 200 |
| ブックマークの解除 | DELETE | `/api/posts/{id}/bookmark` | 200 |
| ブックマークの一覧 | GET | `/api/bookmarks?before=` | 200 |

### 3.5 タイムライン(TL)

#### タイムラインの取得(F-TL-01〜03, F-TL-06〜08)
`GET /api/timeline?tab=…&before=`

| `tab` | 対象 |
|---|---|
| `all`(省略時) | 全ユーザーの投稿(F-TL-01) |
| `following` | 自分と、自分がフォローしているユーザーの投稿(F-TL-02) |

- 返信は含めない(F-TL-06)
- 表示ルール 1.6 で絞る(F-TL-07, F-TL-08)
- 新しい順に最大 20 件(F-TL-03)。続きはカーソル方式(1.5)

#### 新着の取り込み(F-TL-04, F-TL-05)
- 新着は SSE(3.8)で届く。画面は、届いた投稿を先頭に足す
- 「フォロー中」タブでは、届いた投稿のうち `author.id` が自分かフォロー中のユーザーのものだけを足す
- SSE が切れて、つながり直したときは、`GET /api/timeline?tab=…&after={画面の先頭の投稿ID}` で、その間に増えた投稿を取り込む(古い順に最大 50 件。それより多いときは `hasMore: true` を返し、画面はタイムラインを読み込み直す)
- 閲覧中の位置がずれないようにする方法は、画面仕様定義書に書く

### 3.6 フォロー(FOLLOW)

#### フォロー・フォロー解除(F-FOLLOW-01, F-FOLLOW-03)
- `PUT /api/users/{handle}/follow` でフォロー、`DELETE` で解除。何度送っても同じ結果
- 自分自身は `400`(「自分自身はフォローできません」)
- ブロックの関係(どちら向きでも)にある相手は `403`(「このユーザーはフォローできません」)
- フォローしたら、相手に「フォロー」の通知を作る(付け直しても通知は増やさない。いいねと同じ)
- 返す JSON: `{"following": true, "followerCount": 31}`

#### 一覧(F-FOLLOW-02)
- `GET /api/users/{handle}/following`: その人がフォローしているユーザー
- `GET /api/users/{handle}/followers`: その人をフォローしているユーザー
- どちらもフォローした新しい順に 20 件ずつ。ユーザーの JSON(1.8)の一覧を返す
- 利用停止中のユーザーと、ブロックの関係にあるユーザーは一覧に出さない

### 3.7 通知(NOTIF)

#### 通知を作るとき(F-NOTIF-01, F-NOTIF-02, F-NOTIF-06)

| 種類 | 値 | いつ | 受け取る人 | 対象 |
|---|---|---|---|---|
| いいね | `LIKE` | 投稿にいいねされた | 投稿者 | その投稿 |
| 返信 | `REPLY` | 投稿に返信された | 返信先の投稿者 | 返信の投稿 |
| フォロー | `FOLLOW` | フォローされた | フォローされた人 | なし |
| メンション | `MENTION` | 本文でメンションされた | メンションされた人 | その投稿 |

次のときは作らない:
- 受け取る人と、操作した人が同じ(F-NOTIF-02)
- 受け取る人が操作した人をブロック・ミュートしている、または操作した人をブロックされている(F-NOTIF-06)
- 返信とメンションが同じ相手に重なったとき(返信の通知だけ作る)

作ったら、受け取る人に SSE で届ける(3.8)。

#### 通知の一覧と既読(F-NOTIF-03〜05)
- `GET /api/notifications?before=`: 新しい順に 20 件ずつ
- 1件の JSON:
```json
{
  "id": 501,
  "type": "LIKE",
  "actor": { "id": 9, "handle": "hanako", "displayName": "はなこ", "avatarUrl": null },
  "post": { "id": 1234, "textPreview": "今日は #SpringBoot の勉強を…" },
  "read": false,
  "createdAt": "2026-11-01T03:20:00Z"
}
```
- `post` は `FOLLOW` のとき `null`。`textPreview` は本文の先頭 40 文字
- 対象の投稿が削除・非表示になった通知、操作した人が利用停止中の通知は一覧に出さない
- 既読にする: `POST /api/notifications/read` に `{"upToId": 501}` を送ると、その ID 以下の自分の通知をすべて既読にする。返す JSON: `{"unreadCount": 0}`
- 未読件数: `GET /api/notifications/unread-count` → `{"unreadCount": 3}`(ログイン直後は `GET /api/auth/me` にも含まれる)
- 通知をクリックしたときの移動先(F-NOTIF-05): `FOLLOW` は相手のプロフィール、それ以外は対象の投稿の詳細画面

### 3.8 リアルタイム配信(SSE)

#### 接続
- 画面は、ログイン後に `new EventSource('/api/stream')` で接続し、ログイン中はつなぎっぱなしにする
- サーバーは、ログイン中のユーザーごとに接続をメモリで管理する(サーバーは 1 台を前提とする)。1人が複数のタブで開いてもよい(1人 5 接続まで。超えたら古いものから切る)
- 接続が切れていないことを確かめるため、30 秒ごとに中身のない合図(コメント行)を送る
- 切れたら、ブラウザが自動でつなぎ直す(`EventSource` の標準の動き)。つなぎ直したときの取りこぼしは、タイムラインは 3.5、未読件数は `GET /api/notifications/unread-count` で取り直す

#### 送るイベント

| イベント名 | いつ | 送る相手 | 中身 |
|---|---|---|---|
| `post-created` | 返信以外の投稿が作られた | 接続中の全員(ただし表示ルール 1.6 で見えない人と、投稿者本人を除く) | 投稿の JSON(1.7) |
| `post-deleted` | 投稿が削除・非表示にされた | 接続中の全員 | `{"id": 1234}` |
| `notification` | 通知が作られた | 受け取る人 | `{"unreadCount": 4, "notification": {…通知の JSON…}}` |

投稿者本人の画面には、投稿の API の結果を使って先頭に足す(SSE では送らない)。

### 3.9 トレンド(TREND)

#### 集計のルール(F-TREND-01〜03)
`GET /api/trends`

- **ハッシュタグ**: 直近 24 時間に作られた投稿(返信を含む)に付いたハッシュタグを、使われた投稿の数の多い順に上位 10 件。同じ数のときは、最後に使われたのが新しい順
- **人気投稿**: 直近 24 時間に作られた、返信以外の投稿のうち、いいねが 1 件以上あるものを、いいね数の多い順に上位 10 件。同じ数のときは新しい順
- どちらも、削除・非表示の投稿と、利用停止中のユーザーの投稿は数えない(1.6 の V-01〜V-03)。人気投稿は、見る人ごとに V-04・V-05 でも絞る
- 集計は呼ばれるたびに行う(少人数のため、集計結果を保存しておく仕組みは使わない)

返す JSON:
```json
{
  "tags": [ { "name": "springboot", "postCount": 12 } ],
  "popularPosts": [ /* 投稿の JSON */ ]
}
```

ハッシュタグの投稿一覧(F-TREND-03): `GET /api/tags/{name}/posts?before=`。そのタグを含む投稿(返信を含む)を新しい順に。表示ルール 1.6 で絞る。

### 3.10 検索(SEARCH)

#### 共通のルール
- 検索する言葉 `q` は、前後の空白を取り除いて 1〜100 文字。空のときは `400`
- 空白(全角・半角)で区切ると、すべての言葉を含むものを探す(「かつ」)
- 大文字・小文字、全角・半角の英数字は区別しない
- 部分一致で探す。日本語の文章も、そのまま文字の並びとして探せる(F-SEARCH-01)

#### 検索の種類(F-SEARCH-01〜05)

| 種類 | API | 対象 | 並び順 |
|---|---|---|---|
| 投稿(F-SEARCH-01) | `GET /api/search/posts?q=&before=` | 投稿の本文(返信を含む) | 新しい順。20件ずつ |
| ユーザー(F-SEARCH-02) | `GET /api/search/users?q=` | ユーザーID・表示名 | ユーザーIDが言葉で始まるものを先に、次にフォロワーの多い順。最大 20 件 |
| ハッシュタグ(F-SEARCH-03) | `GET /api/search/tags?q=` | タグ名(先頭の `#` は無視する) | タグ名が言葉で始まるものを先に、次に投稿数の多い順。最大 20 件 |

- 投稿の検索結果は、表示ルール 1.6 で絞る(F-SEARCH-05)
- ユーザーの検索結果からは、利用停止中のユーザーと、ブロックの関係にあるユーザーを除く。ミュート中のユーザーは表示する(ミュートを解除できるように)
- ハッシュタグの検索結果は `{"name": "springboot", "postCount": 120}` の一覧

### 3.11 ブロック・ミュート(BLOCK)

#### ミュート(F-BLOCK-01)
- `PUT /api/users/{handle}/mute` でミュート、`DELETE` で解除。何度送っても同じ結果。自分自身は `400`
- ミュートしても、相手には何も知らせない。相手の画面にも変化はない
- ミュートした相手の投稿は、一覧から除く(1.6 の V-05)。相手からの通知も作らない

#### ブロック(F-BLOCK-02)
- `PUT /api/users/{handle}/block` でブロック、`DELETE` で解除。自分自身は `400`
- ブロックしたときに、お互いのフォローを解除する(解除したことは通知しない)
- ブロックの関係にある間は、お互いに次ができない: 投稿を見る(1.6 の V-04)、フォロー、返信、いいね、通知を送る
- ブロックされた側がブロックした人のプロフィールを開くと `404`(「ページが見つかりません」)
- すでにあるいいね・返信は消さない(ブロックを解除したらまた見える)

#### 一覧(F-BLOCK-03)
- `GET /api/me/blocks`、`GET /api/me/mutes`: ブロック・ミュートした新しい順に、ユーザーの JSON(1.8)の一覧を返す

#### API

| 操作 | メソッド | URL | 成功 |
|---|---|---|---|
| ミュート | PUT | `/api/users/{handle}/mute` | 204 |
| ミュートの解除 | DELETE | `/api/users/{handle}/mute` | 204 |
| ブロック | PUT | `/api/users/{handle}/block` | 204 |
| ブロックの解除 | DELETE | `/api/users/{handle}/block` | 204 |
| ミュートしたユーザーの一覧 | GET | `/api/me/mutes` | 200 |
| ブロックしたユーザーの一覧 | GET | `/api/me/blocks` | 200 |

### 3.12 管理者機能(ADMIN)

#### 共通(F-ADMIN-01, F-ADMIN-06)
- `/api/admin` で始まる API は、管理者だけが使える。管理者以外が呼ぶと `404`(管理者の機能があることを知られないため)
- 管理者にするには、データベースで `users.role` を `ADMIN` に変える(画面からはできない)
- 管理者の操作は、いつ・誰が・何をしたかをログファイルに残す

#### ユーザーの管理(F-ADMIN-02, F-ADMIN-05)
- 一覧 `GET /api/admin/users?q=&page=`: ユーザーID・表示名・メールアドレスの部分一致。登録の新しい順に 50 件ずつ(ページ番号は 0 から)
- 1件の JSON: ID・ユーザーID・表示名・メールアドレス・権限・利用停止中か・投稿数・登録日時
- 利用停止 `PUT /api/admin/users/{id}/suspension` に `{"suspended": true}`、解除は `{"suspended": false}`
  - 停止すると、そのユーザーのセッションをすべて消し、SSE の接続も切る
  - 自分自身と、他の管理者は停止できない(`400`)

#### 投稿の管理(F-ADMIN-03, F-ADMIN-04)
- 一覧 `GET /api/admin/posts?q=&page=`: 本文の部分一致。新しい順に 50 件ずつ。非表示の投稿・利用停止中のユーザーの投稿も含めて表示し、それぞれ印を付ける。削除済みの投稿は含めない
- 非表示 `PUT /api/admin/posts/{id}/visibility` に `{"hidden": true}`、解除は `{"hidden": false}`
  - 非表示にすると、SSE で `post-deleted` を配信し、開いている画面から消す
  - 投稿者の画面では、自分の投稿に「管理者により非表示になりました」と表示する(プロフィールの自分の投稿一覧のみ)

| to_user_id | bigint | ○ | された人(users.id) |
| created_at | timestamptz | ○ | 作成日時 |

`(from_user_id, to_user_id)` で一意。`from_user_id` と `to_user_id` が同じ行は作らない。

### hashtags(ハッシュタグ)・post_hashtags(投稿とタグの対応)

| テーブル | 列 | 内容・制約 |
|---|---|---|
| hashtags | id | 主キー |
| hashtags | name | varchar(50)。小文字の半角にそろえたタグ名。一意 |
| post_hashtags | post_id | posts.id |
| post_hashtags | hashtag_id | hashtags.id |
| post_hashtags | created_at | 投稿日時(トレンドの集計を速くするため、投稿の日時を写しておく) |

`post_hashtags` は `(post_id, hashtag_id)` で一意。索引: `(hashtag_id, created_at)`

### notifications(通知)

| 列 | 型 | 必須 | 内容・制約 |
|---|---|---|---|
| id | bigint | ○ | 主キー |
| recipient_id | bigint | ○ | 受け取る人(users.id) |
| actor_id | bigint | ○ | 操作した人(users.id) |
| type | varchar(10) | ○ | `LIKE` / `REPLY` / `FOLLOW` / `MENTION` |
| post_id | bigint | | 対象の投稿(`FOLLOW` のときは空) |
| read_at | timestamptz | | 既読にした日時。未読のときは空 |
| created_at | timestamptz | ○ | 作成日時 |

索引: `(recipient_id, id)`。`LIKE` と `FOLLOW` は `(recipient_id, actor_id, type, post_id)` が同じ通知を 2 つ作らない。

### ファイルの保存場所

| 種類 | 保存場所 | 配信する URL |
|---|---|---|
| 投稿の画像 | `uploads/posts/年/月/推測できない名前.拡張子` | `/media/posts/…` |
| アイコン画像 | `uploads/avatars/推測できない名前.拡張子` | `/media/avatars/…` |
| ヘッダー画像 | `uploads/headers/推測できない名前.拡張子` | `/media/headers/…` |

`uploads` の場所は環境変数 `UPLOAD_DIR` で変えられる。画像の配信はログイン中のユーザーだけに行う。

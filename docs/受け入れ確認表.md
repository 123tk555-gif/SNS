| 記号 | 意味 |

## 確認結果

| No. | 確認内容 | 結果 | 確かめた方法 |
|---|---|---|---|
| AC-01 | メール・Google で登録・ログイン・ログアウトできる。確認メールは Mailpit で受け取れる | ◎ メール / ○ Google | メール: `AuthApiTest`(11 件)と、画面の操作テスト `m2-auth-flow`(登録→確認メール→初期設定→ログアウト→ログイン→パスワード再設定)。Google: 開発者本人が実際の Google アカウントでログインできることを確認(Google の画面を通るので自動テストにはしていない) |
| AC-02 | 1000 文字を超える投稿・11 枚以上の画像は、画面からも API からもできない | ◎ | `PostApiTest`(1000 文字・11 枚・5MB 超・画像でないファイル)、`m3-post-flow`(画面側の制限) |
| AC-03 | 自分の投稿は編集・削除でき、他人の投稿は API を直接呼んでもできない | ◎ | `PostApiTest`「他人の投稿は、APIを直接呼んでも編集・削除できない」、`m3-post-flow` |
| AC-04 | 2 つのブラウザで別ユーザーとしてログインし、一方の投稿が、もう一方に再読み込みなしで表示される | ◎ | `StreamApiTest`、`m6-realtime-flow`、公開用の構成の確認 `prod-smoke`(HTTPS の入り口を通して) |
| AC-05 | いいね・返信・フォロー・メンションで、相手の未読バッジが再読み込みなしで増える | ◎ | `NotificationApiTest`、`StreamApiTest`、`m6-realtime-flow` |
| AC-06 | 「フォロー中」タブには、自分とフォロー中のユーザーの投稿だけが出る | ◎ | `ProfileApiTest`、`m5-follow-flow` |
| AC-07 | ブロックすると、お互いのタイムライン・検索結果から相手の投稿が消え、フォローが解除される | ◎ | `BlockMuteApiTest`(7 件)、`m8-relation-flow` |
| AC-08 | 日本語のキーワードで投稿を検索できる | ◎ | `SearchApiTest`(全角・半角・大文字小文字を区別しない)、`m7-search-flow` |
| AC-09 | ハッシュタグ付きの投稿が、トレンドの件数に反映される | ◎ | `HashtagsTest`、`SearchApiTest`、`m7-search-flow` |
| AC-10 | 管理者以外は `/admin` と管理者の API を使えず、非表示にした投稿はタイムラインから消える | ◎ | `AccessControlTest`、`AdminApiTest`(7 件)、`m9-admin-flow`(開いている画面から再読み込みなしで消えるところまで) |
| AC-11 | 幅 375px で、横スクロールなしに全画面を操作できる | ◎ | `e2e/a11y-audit.mjs`(全画面 × 375px・1280px × ライト・ダークで、横スクロール・名前のない部品・フォーカスの枠などを点検)。各画面の操作テストにも「スマホ幅で横スクロールなし」を入れている |
| AC-12 | 自動テスト(JUnit・Playwright)と oxlint がすべて成功する | ◎ | `mvnw test` 94 件成功、`npm test`(`e2e/`)8 本・計 173 項目成功、`npm run lint` で警告・エラーなし |
| AC-13 | AWS 上に HTTPS で公開され、URL からアクセスして利用できる | △ | 公開用の構成(`compose.prod.yaml`)は、手元で HTTPS の入り口(Caddy)を通して動作確認済み。AWS への公開は、これから |

## 非機能要件のうち、AC に入っていないものの確認

| 要件 | 結果 | 確かめた方法 |
|---|---|---|
| NF-SEC-04 Cookie の属性 | ◎ | `CookieAttributesTest`(HttpOnly・SameSite=Lax)、`prod-smoke`(公開用の構成では Secure も) |
| NF-SEC-05 CSRF 対策 | ◎ | `AccessControlTest` |
| NF-SEC-07 本文を HTML として解釈しない | ○ | React が文字として表示する。本文のリンクは `http(s)://` だけを URL として扱う(`javascript:` などは作らない) |
| NF-SEC-10 公開時はデータベースを外に公開しない | ○ | `compose.prod.yaml` でデータベース・アプリの `ports` を書かず、外に開くのは Caddy の 80/443 だけ。手元で動かして、外からアプリのポートにつながらないことを確認 |
| (追加)画面の読み込み元の制限 | ◎ | Content-Security-Policy・X-Frame-Options・nosniff・Referrer-Policy を全応答に付ける(`AccessControlTest`) |
| NF-PERF-04 メモリ 1GB のサーバー | ○ | 公開用の構成を動かしたときの合計メモリ: アプリ約 405MB・データベース約 57MB・Caddy 約 13MB |
| NF-A11Y-04 色の差 | ○ | 本文・補足の文字・ボタンの文字は、ライト・ダークとも 7 以上(AAA)。入力欄・ボタンの枠線は 3 以上(`--control-border`) |
| NF-OPS-01 ログ | ○ | `logs/sns.log` に保存(10MB ごとに切り替え、30 日分) |
| (追加)画像の S3 保存 | ◎ | `S3StorageApiTest`(S3 の代わりの S3Mock で、保存・配信・削除・ログインしていない人には渡さないこと)。公開用の構成でも S3Mock を使って、投稿の画像が S3 に保存・表示されることを確認 |
| (追加)バックアップ・ログの S3 保存 | ○ | `deploy/aws/s3-tasks.sh` を、手元の公開用の構成と S3Mock で確認(バックアップ → 投稿を消す → 戻すと元に戻る。ログの転送)。毎日動かすタイマーの書式は Amazon Linux 2023 で確認。実際の AWS ではまだ動かしていない |
| NF-ENV-01 ブラウザ | ○ | Edge(Chromium)で確認。Chrome は同じエンジン。Safari・Firefox は確かめていない |

## 確かめていないこと
- Safari・Firefox・実機のスマートフォンでの表示と操作
- Maven の依存部品の既知の脆弱性の検査(`npm audit` は 0 件。Maven 側は検査ツールを入れていない)
- Amazon SES など、実際のメール送信サーバーでの送信(開発中は Mailpit)
- 長時間の運用(セッションの期限切れ、ログの切り替えなど)
